# Release Packaging Assets

The release script copies everything under `packaging/release-assets` into the root of the generated package before adding the built DLL, generated end-user HTML guides, generated changelog, `LICENSE`, `THIRD_PARTY_NOTICES.md`, updater/launcher executable, and installer-ready version markers.

Use this directory as a mirror of the package layout. For example:

```text
packaging/release-assets/
  rerelease/
    baseq2/
      server-base.cfg
      CONFIGS_README.md
      muffmode-map-pool.example.json
      muffmode-map-cycle.example.txt
      gt-FFA.cfg
      gt-DUEL.cfg
      gt-LMS.cfg
      bots/
        navigation/
          example.nav
      maps/
        example.ent
```

The `muffmode-0.22.15-beta.zip` package used this shape:

```text
muffmode-0.22.15-beta/
  README.md
  MuffModeUpdater.exe
  rerelease/
    baseq2/
      game_x64.dll
      muffmode-version.json
      muffmode.version
      server-base.cfg
      CONFIGS_README.md
      muffmode-map-pool.example.json
      muffmode-map-cycle.example.txt
      gt-*.cfg
      bots/navigation/*.nav
      maps/*.ent
      maps/*.bsp
```

New packages generated by `scripts/release.ps1` use the same top-level folder shape, but include an end-user `README.html`, audience-focused `CHANGELOG.md`, `MuffModeUpdater.exe`, and updater-readable version markers in `rerelease/baseq2`.

When localized guides are generated, the English `README.html` includes a language switcher and the installer ships translated siblings: `README.de.html`, `README.pl.html`, `README.fr.html`, `README.hu.html`, and `README.bg.html`. English-only local packages keep a self-contained English language switcher.

Every generated package must include `LICENSE` and `THIRD_PARTY_NOTICES.md` at the package root.

The same staged package root is also compiled into `muffmode-<version>-<channel>-windows-installer.exe` through [packaging/installer/muffmode-installer.iss](installer/muffmode-installer.iss). The installer fails compilation if the staged package is missing required user-facing files, any expected translated guides, updater files, version markers, original-map readme bundle, custom map BSPs, selected entity overrides, server config bundle (including the map-pool and map-cycle examples), `rerelease/baseq2/game_x64.dll`, or the launcher icon. The compiler also embeds SHA-256 hashes for the packaged DLL, updater, docs, included translated guides, legal notices, version manifest, original-map readmes, custom map BSPs, selected entity overrides, server/gametype config files, and map-pool/map-cycle examples so the installed payload can be verified after copy.

The Windows installer presents detected Steam, Epic Games Store, GOG, and Xbox app / Microsoft Store paths, keeps an other-location choice available, shows the resolved target on the Ready page, and offers Desktop/Start menu shortcuts for the updater/launcher, install guide, changelog, and server config guide. During install it corrects accidental `rerelease` or `baseq2` folder selections, requires a real Quake II root with `rerelease/baseq2` and a known launcher executable, rejects extracted Muff Mode package roots plus unsafe system/special-folder/temp/backup-folder targets and reparse-point payload/backup paths, registers the existing DLL/updater for close-applications handling, checks that the target `baseq2` folder is writable, warns if Quake II appears to be running, bounds automatic backup count and size with reserved disk space, skips duplicate backups when the existing DLL already matches the package, backs up previous Muff Mode version marker files beside the DLL backup when present, verifies installed docs/legal/original-readme/custom-map/entity/config/version-manifest contents, verifies exact packaged gametype config contents, and writes `rerelease/baseq2/muffmode-install-receipt.txt` after a verified install.

# MuffMode Changelog

[README](../README.md) | [Release Process](release-process.md)

This is the central change ledger for MuffMode. Every implementation should leave one grouped, user-readable row here before it is considered complete. Review the existing `Unreleased` rows first: if the new work belongs with an existing change, edit that row's summary, details, category, or magnitude instead of adding a near-duplicate row.

`Release` stays `Unreleased` until the release script stamps it with the shipped version. `Magnitude` is release-note impact: `major` changes are eligible for release highlights, `minor` changes are notable but not headline material when major changes exist, and `patch` changes are narrow fixes or maintenance.

| 0.70.28 | Server Hosting | minor | `factory info` shows the ruleset and the map directives, and `factory reload` reports what actually happened | `factory info` listed only the `set` lines, hiding the ruleset, rotation, map pool and player limits — most of what a shipped preset carries — while being documented as showing "exactly what one changes". `factory reload` printed "Factory registry reloaded" even when the document failed to parse and the previous registry had been kept, sending a host who mistyped an edit looking anywhere but the console. | 0.70.28 | Server Hosting | major | Per-gametype `gt-*.cfg` config files are retired; factories replaced them entirely | A gametype change used to exec a config file named after the mode, which meant an arbitrary console command file ran asynchronously at a moment nothing else controlled. It needed a bounded command-buffer filter to keep an operator config from resizing the client slab mid-session, its writes were unattributable so nothing could be restored when the mode changed again, and it could only ever express one flavour per gametype. All eleven shipped presets are gone, along with `g_gametype_cfg` and the exec filter. Everything they carried now lives in a factory, which is data rather than commands: the shipped `factories.cfg` grew eleven hidden `_base_<mode>` entries reproducing exactly what each preset did, and the 53 visible presets inherit them. Only 38 of the 201 settings the presets wrote actually differed from a registered default, which is why the replacements are short. Per-mode `hostname` is gone permanently -- a vote must not be able to rename a server -- and `server-base.cfg` now owns identity, capacity, voting and admin policy outright. `exec gt-FFA.cfg` and friends no longer work: `exec server-base.cfg` then `factory <id>` replaces them. |
| 0.70.28 | Server Hosting | minor | Factories carry map rotations and player limits as validated directives | A map rotation could not survive a `set` line: the shipped CTF list is 94 characters against a 63-character override limit, and a map token is interpolated straight into a `gamemap` command, so a raw string was both too small and unchecked. `maps`, `mappool`, `rotation` and `players` are first-class factory directives instead. Map tokens go through the same validation the structured map system applies everywhere else, rotations are named (`sequential`, `shuffle-on-wrap`, `shuffle-per-gametype`) rather than numeric, and the player limits are range-checked against each other. A child factory that names its own `maps` replaces the inherited rotation rather than extending it, so an Insta CTF variant does not inherit the deathmatch maps it was overriding. |
| 0.70.28 | Server Hosting | minor | Hosts can pin the gametype, and the allowlist a factory may write grew to cover every mode | `g_gametype_locked 1` refuses every gametype and factory change from an admin command or a passed vote, for a server that plays one mode and stays there; the server console and rcon stay exempt so an operator cannot lock themselves out of their own server. The cvar allowlist a factory may `set` grew from 47 to 219 names, covering the full Arena, Freeze Tag and Horde tuning surfaces that previously only a preset could reach, while still excluding server identity, the client slab, authentication and every engine-owned namespace. |
| 0.70.28 | Server Hosting | patch | `factory cvars` lists what a factory may set, and reserved ids are rejected | An author writing a factory had no way to see the allowlist from in-game, and `factory diag` pointed at a `factory cvars` command that did not exist. It does now, with an optional prefix filter (`factory cvars g_arena`). Separately, `factory <id>` shares its argument slot with the subcommands, so a definition named `none`, `list`, `cvars`, `diag`, `info`, `reload`, `clear` or `all` used to register a factory nobody could ever select -- `factory none` would clear instead. Those ids are now rejected at load with the reason. |

| 0.70.28 | Gameplay and Balance | major | Instagib and NadeFest are modifiers again rather than gametypes | Both existed twice: as `g_gametype` values 12 and 13, and as the `g_instagib` / `g_nadefest` cvars. Every one of the seventeen gameplay sites that cared had to ask for both -- `(g_instagib->integer \|\| GT(GT_INSTAGIB))` -- because either representation could be the live one, and the gametype half could not be combined with anything: Instagib CTF and NadeFest Clan Arena were unreachable, since selecting Instagib meant *not* selecting CTF. | 0.70.28 | Server Hosting | major | A 53-entry factory catalogue ships with the mod | The factory system arrived with almost nothing to select. `baseq2/factories.cfg` now carries a classic and a competitive variant of every gametype plus the modifier presets for the modes where each one makes sense: `instagib`, `instactf`, `instaca`, `instaduel`, `instarr`, `vampffa`, `vampca`, `vampctf`, `frenzyctf`, `nadefest`, `quadhog`, rocket-start deathmatch, endless and hardcore Horde, and hidden `_sandbox` / `_horde_soak` entries for testing. | 0.70.28 | Server Hosting | major | Factories: named gameplay presets that layer on a base gametype, so one server can offer several flavours of a mode | A gametype had exactly one `gt-*.cfg` preset, so running classic CTF and Insta-CTF meant running two servers. A factory names a base gametype plus an ordered set of cvar overrides and structured directives, defined as data in `baseq2/factories.cfg` rather than as console commands, and layers on top of whatever the operator's own `server-base.cfg` produced -- which keeps server scope such as hostname, client capacity and admin policy outside anything a factory or a vote can reach. Every cvar a factory writes is recorded with the value it had beforehand, so switching factories restores exactly what the outgoing one changed and re-applies nothing else; this is why factories may only set cvars on a fixed allowlist that excludes server identity, the client slot allocation, authentication and every engine-owned namespace. Weapon damage and projectile numbers stay with the ruleset, which a factory may select by name but never override. New `factory` command (list, info, diag, reload, select) with an `sv factory` equivalent for dedicated consoles, `callvote factory` on vote flag `131072`, and `g_factory` / `g_factory_file` / `g_votable_factories` / `g_factory_title` cvars. Built-in factories are identities only -- one per gametype, changing nothing -- so a factory title can never advertise settings it does not apply. A bad definition is rejected on its own with file, line and reason, and the previous working registry survives a bad edit. |
| 0.70.28 | Fixes | major | Gametype changes are now one transaction instead of three uncoordinated writers | The gametype had no owner: the admin command mutated cvars inline, a per-frame poller mutated a different set, and the gt-cfg preset mutated a third asynchronously -- and two of them could each queue their own map reload in the same frame. Every change now resolves, validates in full, plans its deltas and commits them in one fixed order at a frame boundary. This fixes a double map load on every vote and admin change; a mid-frame team wipe that the same frame's warmup tick then fought by putting everyone straight back; an admin re-applying the current gametype flipping the whole server to Team Deathmatch on the next frame; clearing the `ctf` cvar promoting a Clan Arena, Horde, Duel or Arena server to Team Deathmatch and reloading the map; a same-gametype vote acting as a disguised map-change vote with map votes disabled; an admin `gametype <current>` jumping maps when preset execution was disabled and the command was therefore a complete no-op; and a late validation failure leaving the cvars written and every client frozen, invisible and un-teamed with no reload to undo it. Client session state is reset on a factory change as well as a gametype change, since `client->sess` survives the map change and would otherwise carry a player's old team into the new mode. |
| 0.70.28 | Fixes | minor | Out-of-range and removed gametype values no longer take effect | `g_gametype 9999` clamped onto the highest enumerator, which is MuffMode Arena and is enabled, so a typo silently selected it instead of the documented safe default; both ends now fall back to Deathmatch. `g_gametype 11` (the removed ProBall slot) passed the range check, so every capability query read an empty flag mask -- no frags, no teams, no rounds -- until the next poller tick, which never runs during a timeout. Range and availability are now decided by one resolver that both the sanitizer and gameplay use, so the two can no longer disagree for a whole level. |
| 0.70.28 | Player Experience | minor | The published gametype name keeps the mode it is modifying, and tracks mid-map changes | A hand-written ladder spelled out all 45 gametype-by-mutator combinations, and anything it missed fell through to a generic arm: NadeFest on Freeze Tag published plainly "NadeFest" with the base mode discarded, and the generic arm spelled Instagib differently from the gametype of the same name. Names are now composed from the gametype table, so Freeze Tag under NadeFest reads "NadeFest Freeze Tag" and Instagib is spelled one way everywhere. Nothing previously polled the mutator cvars, so enabling one mid-map never updated the HUD; the name is now recomposed when anything feeding it moves, and rewritten only when the result actually differs. An active factory publishes its own title. |
| 0.70.28 | Internal Maintenance | minor | One gametype descriptor table replaces six index-parallel tables | Short names, uppercase config names, long names, capability flags, availability and spawn-filter tokens each lived in their own array in a different file, with nothing forcing them to agree; the capability array was even declared with a fixed size against a definition sized only by its initialiser, so a short table would have read off the end. All six are now generated from one descriptor table whose self-consistency -- unique names, coherent flag combinations, config-safe filenames, matching score models -- is proven at compile time, and the legacy arrays remain as subscript-compatible projections so no call site changed. Two capability flags were added because they each replace a gametype list that was written out by hand in more than one place and had to be kept in sync manually: the techs vote and its menu row, and the four sites that spelled out the two life-counter modes. | 0.70.28 | Player Experience | major | Gibs and debris were rebuilt from stock assets that shipped with the game but were never used | Vanilla throws eight to forty-six copies of the same meat chunk, fullbright so they read as glowing blobs in a dark room, spinning on a fixed random tumble, landing in silence and then sinking through the floor. Player deaths now mix in the leg, bone, forearm, arm and torso models the base game already precaches for monsters but never gave to a player, scaled by how far past the gib threshold the victim went. Gibs take map lighting, vary slightly in size, fly nose-first along their velocity so bones and limbs stop drifting sideways, settle flat when they come to rest, and fade out as they sink. Landing now produces a blood or spark burst and one of the three unused `player/gibimp*` impact sounds, rate-limited per gib and server-wide; a gib that reaches a sky brush is removed instead of bouncing off the inside of the skybox. Water finally applies: toss physics had no water handling at all, so gibs fell through a pool exactly as they would through air, and they now drag, drift and trail bubbles. The launch bound was also reworked -- vanilla clamped each axis to 300 separately, which squared off the spray and threw away the knockback the killing blow had already applied, so a rocket and a shotgun produced the same symmetric puff. `g_gib_enhanced 0` restores id's original behaviour exactly. Requires no custom content. |
| 0.70.28 | Fixes | patch | Widow gibs spawned at positions computed from uninitialised memory | `ThrowWidowGibReal` read a `size` vector that was declared and never assigned, then scaled its spawn jitter by it. Every caller that passes no explicit start position went through it, including the sixteen gibs `widow2_die` throws, so gib placement depended on whatever floats were left on the stack. |
| 0.70.28 | Fixes | patch | Weak barrels dropped their debris straight down instead of blowing it outwards | `ThrowGibs` takes an integer, and for debris that value is the outward velocity multiplier rather than a damage figure. `misc_explobox` passed `1.5 * dmg / 200`, which truncates to zero for any barrel with `dmg` at or below 133, leaving the chunks with nothing but the barrel's own velocity. Head gibs that failed all three placement probes also no longer end up embedded in whatever geometry the last probe hit. |
| 0.70.28 | Server Hosting | minor | A live-gib budget keeps a busy server's entity pool safe | Running out of entity slots is a hard error that drops the server, and a single deep overkill can cost fifty-eight of them. `g_gib_max` caps live gibs and retires the oldest when the cap is reached, so the newest death always looks right and gib counts can be raised safely on large servers. |
| 0.70.28 | Gameplay and Balance | major | Frozen bodies can be shot around the map, the way Quake 3 freeze tag played | Playtest feedback was that bodies would not budge. Knockback was in fact being applied all along, but toss physics ignores a resting entity, so the velocity was stored on the body and never integrated -- and three things had to change before a shove was visible. Weapons that carry no kick of their own and rely on splash now fall back on knockback derived from damage, capped at 200, for frozen targets only. A shove clears ground contact and adds a small lift so physics will move the body, and the accumulated speed is capped so a shotgun's pellets cannot stack into a map-crossing launch. Frozen bodies also slide on their own friction rather than the heavy damping meant for gibs, which parked a shove inside about one body-width; they keep the standard rest rule, so gravity cannot hold a body above a private threshold and creep it down every ramp it lands on. The grapple pull on a frozen enemy, which had never worked on a grounded body for the same reason, now drags it. Four `g_freezetag_frozen_*` cvars tune the feel, and setting the knockback scale to `0` restores immovable bodies. |
| 0.70.28 | Fixes | patch | Bots no longer lie flat while thawing a teammate | The rescuer's model would pitch about 117 degrees, past horizontal, for the whole thaw. Aiming a bot at a frozen body stored the raw result of a direction-to-angles conversion as its view angle, and that helper reports a downward look as a large negative pitch. The model-pitch calculation only folds angles above 180 before dividing by three, so the raw value fell through and rendered the bot on its back. Bot aim was never affected, since the vectors it derives are periodic; only the model was. The look angle is now normalized into the range a human player's movement code can produce. |
| 0.70.28 | Fixes | patch | A frozen body can no longer strand its owner or jam a door | Nothing could destroy a frozen body -- damage returns before health is touched and its air supply is refreshed every frame -- which mattered little while bodies were welded to the floor and matters a great deal now that they slide. A body left in lava or slime, or pushed out of the world, is destroyed and its owner respawns with no thaw credit or score to anyone; the lava timer is deliberately far slower than a rescue and pauses while a teammate is actively thawing, so dying in a hazard is never the cheap way out. A body blocking a door or platform is instead shifted clear and left frozen, because destroying it there would make shoving a teammate into the nearest door a faster and safer substitute for thawing them. Bodies are inert to triggers and touch callbacks, so they no longer open doors, press buttons, ride jump pads or take teleporters, and one can never telefrag a player spawning on top of it. Frozen bodies also stopped discarding their lag-compensation history every frame, so shots at a sliding body register where they were aimed, the owner's third-person view of their own body interpolates instead of snapping once per tick, and servers running with player collision disabled no longer get it back through the body. |
| 0.70.28 | Internal Maintenance | patch | Cppcheck reports in CI instead of blocking on an untriaged baseline | Once the analysis job could actually run, Cppcheck reported 190 findings across the vanilla, upstream, and vendored tree at its `warning,performance,portability` level -- 112 of them the `uninitvar` family, which is Cppcheck not modelling `vec3_t`'s default constructor, 18 the engine-owned `gentity_t` memsets already annotated for clang-tidy, and 12 inside vendored `{fmt}`. Blocking on that baseline before it is triaged would gate every change on prior findings, so the CI step is informational again and the tooling contract records that as the deliberate state rather than merely permitting it. The full report is still produced and uploaded, the local push verifier still treats findings as blocking, and `.cppcheck-suppressions` stays empty so triage happens per finding with its paired inventory entry, the same way the clang-tidy ratchet widens only as families are reviewed. |
| 0.70.28 | Fixes | patch | Velocity friction and the infantry aim table stop reading past their bounds | The blocking static-analysis ratchet reported three out-of-bounds reads once it could actually run over the tree.
